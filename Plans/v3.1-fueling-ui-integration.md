# v3.1 Fueling Engine UI Integration

**Goal:** Surface the v3 science-backed fueling prescription (pre/during/post/daily/warnings/timeline) through the existing planner UI, behind the existing `settings.engineVersion` flag. Keep v2 working unchanged.

**Scope (pragmatic MVP):**
- Reuse the existing planner Step 1 (kit) and Step 2 (ride data) flow.
- When `engineVersion === 'v3'`, Step 3 renders a new `FuelResultV3` view populated by `buildPrescription()` instead of the v2 `FuelResult`.
- No new ride-form fields in this pass — the v3 engine derives everything it can from the existing ride characteristics plus the athlete profile. Fields not exposed (start time, next session, humidity, purpose override) remain undefined and show up as "missing" in the confidence badge.
- Add a single preference toggle in the Athlete page to flip engines.

## Pieces to build

1. `Plans/v3.1-fueling-ui-integration.md` — this file.
2. `src/lib/fueling/adapters/from-v2-inputs.ts` — pure mapping function:
   - `AthleteProfile` → `RiderProfile`
   - `RideCharacteristics` → `SessionPlan`
   - `HeatFactor` + `TemperatureUnit` → `Environment`
   Returns a full `FuelingInput`.
3. `src/hooks/use-fueling-engine.ts` — returns `{ version, buildV3 }`; `buildV3` is null when v2 is selected or when required rider data (mass) is missing.
4. `src/components/planner/fuel-result-v3.tsx` — displays a v3 `FuelingPrescription`:
   - Context summary (duration, IF, effective heat, purpose)
   - Pre-ride card (carbs, protein, caffeine, notes)
   - During-ride card (g/h carbs, mL/h fluid, mg/h sodium, strategy, pack list bottles + solids)
   - Post-ride card (mode + window(s))
   - Daily targets card (CHO, protein, caffeine ceiling)
   - Carb-load banner if present
   - Warnings list (severity-colored)
   - Confidence summary
   - Timeline (reuse look from v2 ride guide)
5. `src/pages/athlete.tsx` — add an engine-version toggle in the Preferences card.
6. `src/pages/planner.tsx` — when `engineVersion === 'v3'` and mass is set, compute a v3 prescription alongside the v2 plan and render `FuelResultV3` at step 3.

## Out of scope (deferred)

- New input fields on the ride form (start time, next session, humidity) — leave until users request them.
- Rider-profile editor for the v3-only fields (dietary flags, caffeine sensitivity, training load selector, sweat [Na]).
- Persisting a v3 prescription to history (v2 `FuelPlan` storage continues to work alongside).
- Product form additions (protein, carb composition). Not blocking; v3 engine already handles `undefined`.

## Mapping details

### AthleteProfile → RiderProfile
| RiderProfile field | Source | Fallback |
|---|---|---|
| `massKg` | `athleteProfile.weightKg` | **required**; if missing, do not run v3 |
| `age` | `athleteProfile.age` | undefined |
| `ftpWatts` | `athleteProfile.ftpWatts` | undefined |
| `sex` | — | `'unspecified'` |
| `trainingLoad` | infer from `ride.durationMinutes`: `<60→light`, `<120→moderate`, `<180→high`, else `veryHigh` | `'moderate'` |
| `doesConcurrentStrength` | — | `false` |
| `sweatRateLph` | `athleteProfile.sweatRateLph` | undefined (engine infers from heat) |
| `heavySweater` | `athleteProfile.heavySweater` | `false` |
| `currentGutCeilingGph` | `athleteProfile.gutTrainingTargetGph` | `65` |
| `caffeineSensitive` | — | `false` |
| `dietaryFlags` | — | `[]` |
| `anthropometricsUnit` | `athleteProfile.anthropometricsUnit` | `'metric'` |

### RideCharacteristics → SessionPlan
- If `autoMetrics.intensityFactor` is present → `inputMode: { kind: 'duration_if', durationMinutes, intensityFactor }`.
- Otherwise, map intensity enum to a representative IF: `recovery 0.55, endurance 0.70, tempo 0.85, threshold 0.92, race 1.00`, and use `duration_if`.
- `purposeOverride`: map intensity enum directly (recovery / endurance / tempo / threshold / race → same purpose name). This gives users a predictable purpose without a new UI control.
- `refuelStopOffsets`: evenly divide duration by `refuelStops + 1` when `refuelStops > 0`.

### HeatFactor + TemperatureUnit → Environment
Use mid-bucket Celsius temperatures:
- cool → 12, moderate → 20, warm → 28, hot → 34
Leave `relativeHumidityPercent` undefined (engine assumes 50%).

## Success criteria

- Toggling `engineVersion` to `v3` on the Athlete page makes the planner render v3 output.
- Weight missing → v3 toggle still works but Step 3 shows a call-to-action to set weight.
- `npm run lint` and `npm run build` remain clean.
- v2 path unchanged in appearance and behavior.
