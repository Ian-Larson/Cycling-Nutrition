# V1.5 Plan: TSS/IF-Based Auto Nutrition Planning

## Summary

Add a dual-mode planner so riders can either:

1. Keep using manual carb targets (current behavior), or
2. Use auto targets derived from any 2 of 3 ride metrics: `Duration`, `IF`, `TSS`.

Auto mode will use formulas from `Plans/deep-research-report.md`, store athlete profile inputs in Settings, and output carbs, hydration, and sodium targets.

## Formula Engine (New Module)

Create `src/lib/calculator/auto-target.ts` with pure functions:

1. Ride metric resolution:
- `TSS = 100 * IF^2 * dur_h`
- `dur_h = TSS / (100 * IF^2)`
- `IF = sqrt(TSS / (100 * dur_h))`

2. Power/energy:
- `NP_w = IF * ftp_w`
- `kJhr = NP_w * 3.6`
- `kJtotal = kJhr * dur_h`

3. Carb target:
- `pct = clamp(0.45 + 0.1*(IF - 0.75), 0.4, 0.5)`
- `gph_raw = pct * kJhr / 4`
- Floors:
  - if `dur_h < 1` and `IF < 0.7` => `0 g/h`
  - otherwise minimum `30 g/h`
  - if `IF >= 0.85` and `dur_h >= 2` => minimum `60 g/h`
- Caps:
  - `90 g/h` default
  - `120 g/h` only if derived intensity is `race` and `gutTrained = true`
- Round recommendation to nearest 5 g/h for UI.

4. Hydration/sodium:
- Hydration:
  - if `sweatRateLph` set: `ml/h = sweatRateLph * 1000`
  - else fallback by heat selector:
    - `cool: 500`, `moderate: 750`, `warm: 1000`, `hot: 1000`
- Sodium:
  - base `500 mg/h`
  - upgrade to `1000 mg/h` if `hot` or `dur_h >= 2` or `IF >= 0.8`
  - add `+500 mg/h` if `heavySweater = true`

5. IF-to-intensity mapping (for existing app logic):
- `<0.60 recovery`
- `0.60–<0.75 endurance`
- `0.75–<0.85 tempo`
- `0.85–<0.95 threshold`
- `>=0.95 race`

## Validation and Edge Cases

1. Require exactly two ride inputs in auto mode.
2. Validate ranges:
- `IF > 0` and reasonable bounds (`0.4–1.3`)
- `TSS > 0`
- Derived duration must be within supported planner range (`30–300 min`).
3. If formula result is invalid (`NaN`, infinity, negative), block calculate with inline error.
4. Preserve manual mode behavior fully for users who do not use auto mode.
5. Persist migration safety:
- Missing new settings keys get defaults.
- Existing saved plans without sodium still render.

## Assumptions and Defaults Chosen

1. Dual mode remains permanent; manual mode is not removed.
2. Auto mode is blocked without saved FTP (no duration-only fallback in this release).
3. Carb recommendation is editable in auto mode, with recommended value retained in metadata.
4. Heat selector remains categorical; numeric temperature input is out of scope for this release.
5. Sodium is surfaced only when auto metrics exist (legacy/manual plans may show blank/hidden sodium).
