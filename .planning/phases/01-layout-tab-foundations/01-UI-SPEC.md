# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1 (Layout & Tab Foundations). Generated by gsd-ui-researcher, verified by gsd-ui-checker. This phase is a **polish-only foundations sweep in a brownfield app** — the contract documents and locks what already exists in `src/index.css` `@theme` and `src/components/ui/`. No new tokens, no new primitives.

## Spacing Scale

Tailwind v4 default scale (every step is a multiple of 4px). The codebase uses Tailwind utility classes (`p-4`, `gap-2`, `space-y-4`) which resolve to this scale. There is **no project-specific spacing token override** in `@theme` — Tailwind defaults are the contract.

| Token | Value | Usage in this codebase |
|-------|-------|-------|
| 0 | 0 | reset |
| 1 | 4px | tight icon gaps, `p-1` segmented-control inner padding |
| 1.5 | 6px | rare; `gap-1.5` in fuel-plan tab grid |
| 2 | 8px | `gap-2` between adjacent controls, sub-nav `mb-2` |
| 2.5 | 10px | `gap-2.5` form grids |
| 3 | 12px | `p-3` mobile card padding, `pb-3` sub-tab divider |
| 4 | 16px | `p-4` desktop card padding, `space-y-4` default vertical rhythm |
| 5 | 20px | `space-y-5` planner page rhythm |
| 6 | 24px | `md:space-y-6` desktop vertical rhythm, `md:gap-6` two-column splits |
| 8 | 32px | `pb-8` (cloud-fallback footer breathing room) |

### Body / control copy details
- Tab labels: `text-sm` (14px) at weight 500, see `src/components/ui/tabs.tsx:168`.
- Form labels: `text-sm`, weight 500.
- Tabular numerics use `font-variant-numeric: tabular-nums` (set globally on numeric inputs and `.tabular-nums` class — `src/index.css:117`).

## Color

Brand: orange `#f8622e` (`--color-brand-500`). Light mode only. **No dark variants in this milestone.**

The codebase uses 60/30/10 across `shell` (warm whites), `ink` (cool grays for text/borders), and `brand` (orange accent), plus semantic `success / warning / error` reserved for status only.

| Role | Token / Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-shell-100` `#ffffff` (page background via `body` `bg-shell-50` and `.app-shell`) | App background, large surface fills |
| Secondary (30%) | `--surface-panel` `#ffffff` + `--border-soft` `color-mix(shell-300 72%, white)` + `--color-ink-50…200` neutrals | Cards, dividers, sub-headers, body text on light bg |
| Accent (10%) | `--color-brand-500` `#f8622e` | Reserved (see list below) |
| Destructive | `--color-error-500` `#f43f5e` / `error-600` `#e11d48` | Destructive actions only — not in Phase 1 scope |

### Accent reserved for (locked list — do not expand without owner approval)
1. **Active state of the canonical tab primitive** — `bg-brand-500 text-white` pill (`src/components/ui/tabs.tsx:172`).
2. **Active state of `SegmentedControl`** — same `bg-brand-500 text-white` pill (`src/components/ui/segmented-control.tsx:60`).
3. **Active state of route-based sub-nav (`GearSubNav`)** — `border-brand-600 text-brand-800` underline (`src/components/gear/gear-sub-nav.tsx:24`). Phase 1 does not change this; it's a `<nav>`, not a tablist.
4. **Primary button background and primary CTA highlights** — existing `Button` primitive variants. Not modified in Phase 1.
5. **Selection/focus rings** — `focus-visible:ring-brand-200` across interactive primitives.
6. **Brand identity surfaces** — header logo, brand-tinted callouts using `--bg-brand-light`.

Accent is **never** used for: full-row hover states, neutral icons, body copy emphasis, table-header backgrounds, badge fills outside the canonical-active styling above.

### Border tokens (locked)
- `--border-soft` — default card / sub-tab divider border.
- `--border-strong` — emphasized boundaries (sparingly).

## Phase 1 Foundations

These five items are the primary deliverables of Phase 1. Phases 2/3/4 mechanically reuse the contracts below.

### 1. Page-shell side padding (LAYOUT-01)

**Owner primitive:** the `.page-shell` CSS utility class in `src/index.css:155-159` (mobile) and `src/index.css:266-270` (desktop md+).

**Locked values:**
- Mobile: `padding-inline: 1rem` (16px) via `@apply px-4`
- Desktop (md+ ≥ 768px): `padding-inline: 1.5rem` (24px)
- Container: `mx-auto max-w-6xl` — fixed centered shell, `max-w-6xl` = 72rem = 1152px

**The rule (binding):**
> Every primary route renders its top-level wrapper as `<div className="page-shell">`. The page MUST NOT add `max-w-*`, `mx-auto`, `px-*`, or `padding-inline-*` overrides on that wrapper. Vertical rhythm (`space-y-*`) is the only utility allowed alongside `page-shell`.

**Migration targets in this phase** (each currently re-declares `max-w-6xl` redundantly — strip it):

### 2. Canonical tab primitive (LAYOUT-02)

**Survivor:** `src/components/ui/tabs.tsx` — `Tabs`, `TabList`, `Tab`, `TabPanel`.

**Rationale (one line):** `Tabs` already implements the full ARIA tablist contract (roles, `aria-selected`, `aria-controls`, panel association via context, roving tabindex), full keyboard interaction (Arrow/Home/End with focus management), and uses the canonical pill styling — `gear-tabs.tsx` is a partial re-implementation, and `SegmentedControl` is semantically a `radiogroup` (different primitive, kept for unit toggles).

**Deprecation target (delete in Phase 1):**
- `src/components/gear/gear-tabs.tsx` — replaced by `Tabs/TabList/Tab` from `@/components/ui`.

**Kept as-is (different semantic role, not a tab control):**
- `src/components/ui/segmented-control.tsx` — `role="radiogroup"`, used for the metric/imperial unit toggle in `athlete.tsx:316`. Stays. Phase 1 does not consolidate this with `Tabs`.
- `src/components/gear/gear-sub-nav.tsx` — `<nav>` of `<NavLink>` route links between `/gear` and `/gear/inventory`. This is route-based navigation, not in-page tabs. Stays.
- `src/components/layout/header.tsx` and `src/components/layout/mobile-nav.tsx` — primary route nav. Out of scope.

**Migration call-sites** (use the canonical `Tabs` family from `@/components/ui`):
| File | Current | Target |
|------|---------|--------|
| `src/pages/gear.tsx:264` (and the surrounding tabpanel divs `src/pages/gear.tsx:271-` for `active`, `due`, `history`) | `<GearTabs value={tab} onChange={handleTabChange} />` plus three hand-rolled `<div role="tabpanel">` blocks using `gearPanelId/gearTabId` | Wrap the section in `<Tabs value={tab} onChange={...}>`, replace `GearTabs` with `<TabList label="Gear view"><Tab value="active">Active setup</Tab><Tab value="due">Service</Tab><Tab value="history">History</Tab></TabList>`, replace each role="tabpanel" div with `<TabPanel value="active">…</TabPanel>` etc. Drop `gear-tab-ids.ts` (id generation handled internally by `Tabs`). |
| `src/pages/planner.tsx:821-833` | Already uses `<Tabs>` / `<TabList>` / `<Tab>` (Pack/Ride guide/Stats) | No structural change. **Visual lock: the `grid w-full grid-cols-3 gap-1.5 md:gap-2` className on `TabList` is allowed** as an instance-level layout adjustment (it stretches the three pills full-width). Keep. |

**Locked behavior of the canonical primitive (from `tabs.tsx`):**
- **Touch target:** `min-h-11` (44px) on mobile, `md:min-h-10` (40px) on desktop. Meets iOS/WCAG 44px minimum on touch.
- **Active styling:** `bg-brand-500 text-white shadow-[0_8px_18px_-16px_rgba(248,98,46,0.8)]` — orange pill with soft drop shadow.
- **Inactive styling:** `text-ink-700 hover:bg-shell-50 hover:text-ink-900`.
- **Shape:** `rounded-full` pill.
- **Typography:** `text-sm font-medium`.
- **Focus:** `focus-visible:ring-2 focus-visible:ring-brand-200 focus-visible:ring-offset-2 focus-visible:ring-offset-shell-100`.
- **Keyboard:** ArrowRight/Down → next tab, ArrowLeft/Up → previous tab, Home → first, End → last; activation moves focus AND changes value (the existing `focusTab` calls `onChange`).
- **Roving tabindex:** selected tab is `tabIndex=0`, others `-1`.
- **Panel association:** `id={baseId}-tab-{value}` paired with `aria-controls={baseId}-panel-{value}` and `aria-labelledby` mirror.
- **`keepMounted` option** on `TabPanel` — used when state preservation matters; default off.

**The rule (binding):**
> No surface in `src/pages/` or `src/components/` may implement its own tablist UI. In-page tab views consume `Tabs/TabList/Tab/TabPanel` from `@/components/ui`. Mutually-exclusive setting toggles (e.g. unit selectors) consume `SegmentedControl`. Route-based section nav consumes `<NavLink>` patterns mirroring `gear-sub-nav.tsx`.

### 3. Touch-target floor (mobile-first)

**Minimum interactive height: 44px (`min-h-11`)** on mobile for any control a rider might tap one-handed before a ride. The canonical tab pill already complies (`min-h-11 md:min-h-10` in `tabs.tsx:168`). `SegmentedControl` complies at `size="md"` (`min-h-11 md:min-h-10`, `segmented-control.tsx:23`). The `GearSubNav` underline links comply (`min-h-11`, `gear-sub-nav.tsx:22`).

**Phase 1 enforcement:** any code touched during the migration MUST preserve `min-h-11` on tab pills and sub-nav links. The size="sm" variant of `SegmentedControl` (`min-h-9` ≈ 36px) is **not** to be introduced on net-new surfaces in this phase; it's grandfathered for any existing call-site (currently none under audit).

### 4. Layout no-shift rule (the success criterion this phase exists for)

**Binding rule:**
> Switching between primary tabs (Fuel Plan ↔ Garage ↔ Account) and between in-page tabs (Active/Service/History; Pack/Ride guide/Stats) MUST NOT change the x-position of the content edge at any breakpoint.

**Why it can shift today:**
- Pages duplicate `max-w-6xl` redundantly. If anyone edits one page's wrapper class without editing the others (e.g. `max-w-5xl`), the shell width drifts per-route.
- The Garage "Due Soon" preview band renders above the tab strip on `active` and `history` and disappears on `due` (handled in Phase 3 GEAR-02). Phase 1's contribution: the tab strip's horizontal position is governed entirely by `.page-shell` padding, not by sibling content.

**How this phase enforces no-shift:**
1. Single source of side padding (`.page-shell` utility) — see Foundation 1.
2. `max-w-6xl` lives in `.page-shell` only — no per-page declarations.
3. The canonical tab primitive renders inside the page-shell padding box; nothing within a tab panel may set negative margins, full-bleed children, or width-expanders that escape the shell.

**Acceptance test (will be referenced by the executor):**
> Open every primary route at 375px (iPhone SE), 768px (tablet breakpoint), and 1280px (desktop). The leftmost pixel of the page H1 (`.page-title`) MUST land at the same x-coordinate across all routes at the same breakpoint. Switching between in-page tabs at any of those breakpoints MUST NOT move that x-coordinate.
